# working with talos

Talos vms on proxmox are **servers**

Host machine running talosctl is **client**

1. install talos if not already installed: https://github.com/siderolabs/talos/releases/latest
    1. add it to $PATH on windows to run it from anywhere
2. check : talosctl version
    
    ```bash
    Client:
            Tag:         v1.12.7
            SHA:         91c63991
            Built:
            Go version:  go1.25.9
            OS/Arch:     windows/amd64
    Server:
    error constructing client: failed to determine endpoints
    #errors are okay, it's because it hasn't been connected to talos control yet - which cluster or node to talk to hasn't been chosen yet, so talosctl can't connect to anything
    ```
    
3. create yaml config files - instructions, rulebooks on what each machine is supposed to become
    1. which cluster this machine belongs to, what its role is (control-plane brain vs worker muscle), the certificates or keys needed to securely join, and the network address of the control plane so it knows where to check in
    2. talosctl **gen config** talos-k8s-cluster https://192.168.169.200:6443 --output-dir talosconf - generates 3 config files in folder talosconf - basically creates talos cluster/group
        
        ![image.png](working%20with%20talos/image.png)
        
    3. talosctl apply-config --insecure --nodes 192.168.169.200 --file talosconf/controlplane.yaml - takes control machine config from the talosconf and sends to the talos-control, command will make it pull image and reboot - **applying control config**
    4. switch boot order from options of vm, and make scsi top 1 - also check scsi, uncheck others
        
        ![image.png](working%20with%20talos/image%201.png)
        
    5. detach talos-control CD from proxmox. **stop** and start vm again
    6. now control is in the cluster: (pay attention that IP changed and needs reconfiguring)
        
        ![image.png](working%20with%20talos/image%202.png)
        
    7. **applying worker config**:
        
        talosctl apply-config --insecure --nodes 192.168.169.201 --file talosconf/worker.yaml
        talosctl apply-config --insecure --nodes 192.168.169.202 --file talosconf/worker.yaml
        
    8. do the same d e step for workers
4. talosctl config endpoint 192.168.169.200 --talosconfig talosconf/talosconfig - cluster wide commands are gonna be sent to talos-control, saving the ip to the file so it won’t ask every time
5. talosctl config node 192.168.169.200 --talosconfig talosconf/talosconfig - node wide commands are gonna be sent to talos-control, like checking logs
6. talosctl bootstrap --talosconfig talosconf/talosconfig - etcd, database that stores cluster’s state, will be started and initialized 
7. install kubectl if not yet installed: 
    1. `curl.exe -LO https://dl.k8s.io/release/v1.36.0/bin/windows/amd64/kubectl.exe`
8. talosctl kubeconfig --talosconfig talosconf/talosconfig . - fetches kubectl personal creds and adds to kubeconfig folder, that makes the use of kubectl command to talk to the cluster
9. $env:KUBECONFIG = "C:\Users\ekapa\kubeconfig" - make kubectl aware which kubeconfig file to read
10. kubectl get nodes - check , run twice after 2-3 mins to have control talos name
    
    ![image.png](working%20with%20talos/image%203.png)
    
11. kubectl describe node talos-control

Bootstrap:

`kubectl get nodes` can see them — that's when each VM stops being just "a machine running Talos" and starts being represented as a **Node**

bottstrap makes them nodes

**talosctl vs kubectl:** 

talosctl = manages the **machine and OS**

kubectl = manages **Kubernetes objects**
