# RBAC

**after creating puppy vm, let users have the puppy vm on their account:**

1. Datacenter → Permissions → Add → Group Permission
2. First entry: Path = `/vms`, Group = `users`, Role = `PVEVMUser`
3. Second entry: Path = `/`, Group = `admins`, Role = `PVEADMIN`

**test:**

**using / and /vms:**

`/vms` + PVEVMUser, and `/` + PVEADMIN:

both folders are used for permissions mainly. 

`/` is the root of everything Proxmox manages: nodes, storage, users, VMs, cluster settings, all of it. 

`/vms` only covers virtual machines.

**Regular users** 

only touch VMs, never storage config, never other users, never the node. Plus the role `PVEVMUser` - a role that only contains VM-related permissions → start/stop/console

**Admins** 

need full control of everything with the role `PVEADMIN` at `/` - the very top, covering everything underneath it, like a master key

**pve vs pam realm:**

PAM users are real Linux user accounts on the underlying Debian OS. they manage a real system-level user (password policies, home directories, SSH access potential, the works). 

PVE realm creates a user that exists only inside Proxmox's own permission system. doesn't touch the actual OS at all. For accounts that only need to click around the Proxmox web UI.
